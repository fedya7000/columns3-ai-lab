# СОСТОЯНИЕ РАБОТЫ — читать первым при возвращении к проекту

Проект: реверс и мод **Columns III (USA)** для Mega Drive.
Папка: `E:\New1\columns3`. Играют на эмуляторе (RetroArch, ядро Genesis Plus GX).

## Готовый файл

**`build\c3_sailor.gen`** — в нём ВСЁ. Пересобрать:

```
python tools\patch.py "rom\Columns III (USA).gen" patches\sailor.py "build\c3_sailor.gen"
```

С другой мелодией: `music.bat 8F`. Только правила без облика: `patches\turnir.py`.

## Что осталось

1. **Послушать мелодию и сказать, где ноты врут.** Формат звука вскрыт до конца,
   своя мелодия записана в ПЗУ и зациклена — но ноты «Лунной легенды» я писал
   ПО ПАМЯТИ, и они вполне могут быть неверными. Правится за минуту: список нот
   лежит в `art\melody.py`, одна строка на ноту.
2. Два зерна из десяти в долгом прогоне падают на `$00E6E8` — запись по дикому
   указателю в отрисовке для пустого слота игрока. Пре-существующее, к правкам
   отношения не имеет (столько же было и до них).

## РАЗБОР ЗВУКА — что уже вскрыто (это главное, что нельзя потерять)

**Дизассемблер Z80: `tools\z80dis.py`** (свой, capstone Z80 не умеет).
Выгрузка драйвера: `python tools\z80dis.py "rom\Columns III (USA).gen" 7552A F76 0 > docs\z80_driver.asm`

**Раскладка звука:**

| что | адрес в ROM | адрес в Z80 | размер |
|---|---|---|---|
| программа драйвера | `$07552A` | `$0000` | 3958 байт |
| данные (таблица + тембры + ноты) | `$0764A0` | `$1000` | 2904 байта |
| команды от 68000 | — | `$1C00` (`$A01C00`) | — |

⚠️ **ГЛАВНАЯ ОПЛАЧЕННАЯ ОШИБКА: ТАБЛИЦ ДВЕ, И `$1000` — ЭТО ЭФФЕКТЫ, А НЕ МУЗЫКА.**
Сперва мелодия была вписана в блок `$1000`, всё сходилось статически — а в игре
звучала родная музыка. Признак, который был виден с самого начала и который я
проглядел: **записи там 17–144 байта и кончаются без зацикливания** — это
короткие эффекты. Отсюда же и жалоба владельца «мелодии звучат чуть-чуть».

**Как на самом деле.** На Z80 `$8000` лежит ШАПКА драйвера с указателями на
разные таблицы; какую взять, решает `ld c,N` перед `rst $08` (`hl = ($1C02)+N`,
и `$1C02` = `$8000` намертво, его пишет только 68000 при старте):

| `c` | слово по | что там | где |
|---|---|---|---|
| `$04` | `$8004` | **`$8255` — МУЗЫКА, 31 тема** | код старта `$04BD` |
| `$06` | `$8006` | `$1000` — звуковые эффекты | код старта `$055A` |

**Номер темы = ID − `$81`** (код `$04B5: sub $81`), то есть **музыка — ID `$81..$9F`**,
всё выше — эффекты. **Музыка живёт в ПЗУ и читается через банковое окно:
Z80 `$8000` = ROM `$070000`** (сошлось по целям переходов). Данные нот —
ROM `$071000..$0755xx`.

**Боевая тема 1on1 — ID `$8D`**: запись ROM `$071D20`, три канала, первый нотный —
Z80 `$A04F` = ROM `$07204F`. Начинается сразу с ноты: тембр задаёт шапка темы,
настройки в начало канала не нужны.

⚠️ **РЕГИСТР:** родная тема играет полутонами 2..21 (октавы 0-1). Своя мелодия
обязана быть там же, иначе пищит поверх музыки.

**Переключение банка ПЗУ** — запись 9 бит в Z80-адрес `$6000` (обработчик
прерывания на Z80 `$0038`), то есть драйвер умеет читать и из ROM через окно
`$8000..$FFFF`.

**Интерпретатор последовательности — Z80 `$08CF`:**

```
08CF: ld e,(ix+3)      ; ix = блок состояния канала, +3/+4 — указатель на ноты
08D2: ld d,(ix+4)
08D5: ld a,(de)        ; взять байт
08D6: inc de
08D7: cp $e0
08D9: jp nc,$097c      ; байт >= $E0 -> КОМАНДА (обработчик $097C)
08DC: or a
08DD: jp m,$08e4       ; байт >= $80 -> НОТА
08E0: dec de           ; байт <  $80 -> откат: повтор ПРЕДЫДУЩЕЙ ноты,
08E1: ld a,(ix+13)     ;                 а сам байт — длительность
08E4: ld (ix+13),a     ; запомнить текущую ноту
08E7: cp $80
08E9: jp z,$0966       ; $80 = ПАУЗА
```

Обработка длительности (Z80 `$0966`):

```
0966: ld a,(de)        ; следующий байт
0967: inc de
0968: or a
0969: jp p,$022a       ; байт < $80 -> это ДЛИТЕЛЬНОСТЬ
096C: dec de           ; байт >= $80 -> откат, берём длительность по умолчанию
096D: ld a,(ix+12)     ; (ix+12) — длительность по умолчанию
0970: ld (ix+11),a
0973: jp $0230
```

**ИТОГО формат нот — ВСКРЫТ ПОЛНОСТЬЮ:**

| байт | что значит |
|---|---|
| `$80` | пауза |
| `$81..$DF` | **нота: номер полутона = байт − `$81`** |
| `< $80` | длительность предыдущей ноты (иначе берётся из `ix+12`) |
| `$E0..$FF` | команда |

Высота ноты (код Z80 `$01B2` и `$01CC`):

```
01B2: sub $81      ; номер полутона = байт - $81
01B7: call $0ec3   ; байт $80 дал -1 -> это ПАУЗА
01BC: add a,(ix+5) ; + транспонирование канала
01CC: ld d,$08     ; дальше: полутон делится на 12 —
01CE: ld e,$0c     ; частное = октава (кладётся в поле блока, шаг 8),
01DC: ld hl,$08b0  ; остаток = индекс в таблице 12 частот
```

**Команды.** Обработчик берёт `байт − $E0` и прыгает по таблице на Z80 `$0ABB`.
Разобраны важные:

| байт | что делает |
|---|---|
| `$F6 мл ст` | **переход по адресу — им и зацикливают мелодию** |
| `$F7 слот N мл ст` | повторить N раз с адреса |
| `$F8 мл ст` / `$F9` | вызов куска / возврат (свой стек в `ix+9`) |
| `$E7`, `$EC`, `$EF`, `$F0`, `$E4` | тембр, громкость, вибрато и прочая настройка |

**Заголовок мелодии** — запись начинается с указателей: первый на данные тембра,
дальше на нотные каналы. У мелодии боя `$8D` это `$13D0` (тембр), `$139F` и
`$13BA` (два нотных канала).

**Проверка понимания:** `python tools\seq_decode.py 13` разбирает родную мелодию
боя и показывает осмысленную музыку — ноты, длительности и «повторить 8 раз» с
адресом, который ведёт назад в тот же канал. Случайно так не совпадает.

## СВОЯ МЕЛОДИЯ — как сделана и как править

Ноты лежат в **`art\melody.py`** обычным списком (`n('sol', 1, E)` — нота,
октава, длительность). Сборка кладёт их в **чистый хвост банка**: Z80 `$F000`,
в ПЗУ `$077000` (там сплошной `$FF`, места 4 КБ) — и уводит туда первый нотный
канал боевой темы командой перехода по ПЗУ `$07204F`. Мелодия кончается
переходом на саму себя — поэтому **играет постоянно, а не обрывается**.

Блок эффектов `$0764A0` при этом НЕ трогается — сверять байт в байт с оригиналом.

⚠️ **Ноты «Лунной легенды» записаны ПО ПАМЯТИ и могут врать.** Проверка — уши
владельца. Поправить: открыть `art\melody.py`, изменить строки, пересобрать.

**Таблица частот — Z80 `$08B0`**, 12 значений по 2 байта (хроматическая октава,
F-number для YM2612): `$0284 $02AB $02D3 $02FE $032D $035C $038F $03C5 $03FF
$043C $047C $04C0`. Отношение соседних ≈ 1.059 — проверено, это полутоны.
Читается кодом на Z80 `$01DC` (`ld hl,$08b0`).

⚠️ **Проверять на слух должен ВЛАДЕЛЕЦ.** Своего звука в эмуляторе нет
(ни Z80, ни YM2612), поэтому единственная проверка — «сыграй и скажи».
В игре для этого есть **SOUND TEST**: меню режимов → вправо 3 раза → вниз →
Start. Там BGM/SE/VOICE и номер, слушать можно всё подряд.

## Грабли, оплаченные дорого

- **Хуки Unicorn показывают PC НЕТОЧНО** на записи в память (отдают начало блока
  трансляции). По нему нельзя называть виновника — проверять кодовым хуком.
- **Хуки ставить ДО загрузки ROM**: движок кеширует оттранслированный код, и
  хук, поставленный позже, молча не сработает.
- **Лечить симптом хуже, чем не лечить.** Заплатка на обработчик `$FF` в
  анимации маскота убрала мусорную заявку DMA, но сбой переехал раньше и в
  другое место. Откатили, нашли причину (номер состояния 176 при таблице в 33
  записи), починили её.
- **Сторож указателя обязан учитывать, КУДА пишут**, а не только откуда: запись
  идёт на 72 байта дальше указателя, и первая граница пропускала мусор.
- **Палитру нельзя слать прямо в CRAM** — игра каждый кадр заливает её из своей
  копии в памяти (`$FF0300` палитра 0, `$FF0320` палитра 1, `$FF0340` палитра 2;
  вторые копии для переходов — `+$80`).
- **НЕ ПРАВИТЬ текстовые файлы через PowerShell** (`Get-Content`/`Set-Content`):
  русские комментарии превращаются в кашу. Только Edit/Write.
- Игра САМА проверяет контрольную сумму (`$000DBA`) и виснет на красном экране
  при несовпадении — `tools\patch.py` пересчитывает её всегда.
- В `tools\patch.py` есть сторож наложения правок — он уже дважды поймал
  налезающие адреса.
