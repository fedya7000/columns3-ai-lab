# Columns III (USA) — карта реверса

ROM: `Columns III (USA).gen`, 524288 байт (512 КБ)
SHA1 `8E52A5D0ADBFF3B2A15F32E9299B4FFDF35F5541` · MD5 `441B7E9C9811E22458660EB73975569C`
Дамп чистый: посчитанная сумма сошлась с заголовком.

## Заголовок картриджа

| поле | значение |
|---|---|
| консоль | SEGA GENESIS |
| копирайт | (C)T-23 1993.DEC |
| название | COLUMNS 3 |
| серийник | GM T-23056 -00 |
| контрольная сумма | `$9F85` (по адресу `$18E`) |
| устройства | `J4` — поддержка 4-портового адаптера |
| регион | U (США) |
| ROM | `$000000..$07FFFF` |
| RAM | `$FF0000..$FFFFFF` |

**Свободный хвост ROM: `$7A386..$7FFFF` — 23674 байта.** Сюда можно класть новый код.

⚠️ **Игра САМА проверяет контрольную сумму на старте.** Код на `$000DBA`: складывает
все слова с `$200` до конца и сравнивает с `$18E`. Не совпало — вечный цикл с красным
экраном (`$000DE2`). Любая правка ROM обязана пересчитывать сумму.

## Точки входа и главный цикл

```
$0000  начальный стек $00FFEF00
$0004  точка входа    $000CA8
$0070  H-Blank        $000200
$0078  V-Blank        $000208   ← главный тик 60 Гц
```

Главный цикл — на `$000E76`:

```
000E76: move.w  $ff0406.l, d0   ; НОМЕР РЕЖИМА ИГРЫ (титры/меню/бой/…)
000E7C: lea.l   $e8e.l, a0      ; таблица режимов, 21 вход
000E82: movea.l (a0, d0.w), a0
000E86: jsr     (a0)
000E88: bsr.w   $ee2            ; ждать кадра
000E8C: bra.b   $e76
```

`$FF0406` — индекс в таблице `$000E8E` (шаг 4 байта). Наблюдавшиеся значения:
`$0C` титульник · `$14` выбор режима · `$1C` настройка боя 1on1 · `$20` сам бой ·
`$24` конец раунда · `$2C` сюжетный режим 1P.

Режимы игры (меню): 1P MODE · **1on1 MODE** · 3P · 4P · 5P · 6P · TEST MODE.

## Игровое поле

Указатель на поле лежит в структуре игрока по смещению **+0x06**.
У первого игрока это `$FF1260`, у второго `$FF1660`.

- ячейка = **СЛОВО** (2 байта)
- ряд = **16 байт** (8 слов: 6 игровых колонок + 2 слова стены)
- поле **6 колонок × 13 рядов**; ряд 13 и ниже — пол
- значения: `$0000` пусто · `$0001..$0006` цвет камня · `$00FF` стена/пол
- выше ряда 0 идут скрытые ряды появления фигуры

## Структура игрока

Пять слотов с шагом `$400`: `$FF1000` · `$FF1400` · `$FF1800` · `$FF1C00` · `$FF2000`.
В бою 1on1 заняты первые два; остальные заранее забиты меткой «выбыл»
(`+0x5C = $1000`), поэтому обход всех слотов безопасен.

| смещение | размер | что это |
|---|---|---|
| +0x00 | слово | номер игрока (1, 2, …) |
| +0x06 | длинное | **указатель на поле** |
| +0x16 | длинное | буфер отрисовки БОЛЬШОГО числа |
| +0x20 | длинное | буфер отрисовки БЕЛОГО числа (правая цифра) |
| +0x24 | длинное | указатель на структуру ПРОТИВНИКА |
| +0x42 | слово | колонка падающей фигуры (0..5) |
| +0x4C | слово | высота завала; `>= 24` = игрок завалился |
| +0x4E | длинное | указатель на клетку поля под фигурой |
| +0x5A | слово | **бирюзовое число на экране** — шкала атаки, потолок 30 |
| +0x5C | слово | **белое число на экране**, потолок 9999. ⚠️ НЕ счёт: его прирост за каскад идёт в `+0x9E` (`$00DF26`) и определяет СИЛУ АТАКИ по сопернику |
| +0x60,+0x62,+0x64 | слова | цвета трёх камней ТЕКУЩЕЙ фигуры |
| +0x6C | слово | **длина цепочки (комбо)** |
| +0x70 | слово | счётчик уложенных фигур |
| +0x76 | слово | ненулевое = начисление запрещено |
| +0x88 | слово | **порядок выбывания**: при смерти сюда пишется общий счётчик `$FF041E`, потом он растёт (`$00EE20`). Кто выбыл ПОЗЖЕ — тот в оригинале и выиграл раунд |
| +0x8C | слово | вторая копия `+0x5C`. ⚠️ игра сама обнуляет её по ходу раунда (`$00D328`) — как накопитель не годится |
| +0x9E | слово | сила атаки, посланной сопернику |
| +0xB4 | длинное | указатель на скрипт анимации петуха-маскота |
| +0xB8 | байт | состояние анимации маскота (индекс в таблице скриптов `$10812`) |
| +0xB9 | байт | номер кадра в скрипте анимации |
| +0xCE,+0xD0,+0xD2 | слова | цвета СЛЕДУЮЩЕЙ фигуры |
| +0xD8 | байт | **побед в матче** (показывается как «1W») |
| +0xD9 | байт | **поражений в матче** (показывается как «0L») |
| +0xDA | байт | ничьих в матче |
| +0xE1 | байт | флаг «этот игрок победил в раунде» — управляет надписью WIN!/LOSE |
| +0xE3..+0xEF | 13 байт | **СВОБОДНО**: во время игры не пишет никто, между раундами обнуляется (замер — `tools\freeslots.py`). Сюда положены турнирные очки (+0xE4) |

В режиме versus обоим игрокам выдаётся ОДИНАКОВАЯ последовательность фигур.

## Ядро начисления — `$00DF62`

```
00DF62: tst.w   $76(a6)        ; a6 = структура игрока
00DF66: beq.w   $df6c
00DF6A: rts                    ; начисление запрещено — выход

00DF6C: tst.w   $6c(a6)        ; есть цепочка?
00DF70: beq.w   $df80
00DF74: move.w  d2, -(a7)
00DF76: move.w  $6c(a6), d2
00DF7A: asl.w   #$2, d2        ; длина цепочки * 4
00DF7C: add.w   d2, d1         ; ← ВЕСЬ бонус за комбо, какой есть в игре
00DF7E: move.w  (a7)+, d2

00DF80: add.w   d1, $5a(a6)    ; бирюзовое += (камни + цепочка*4)
00DF84: cmpi.w  #$1e, $5a(a6)  ; ПОТОЛОК 30
00DF8A: ble.w   $df94
00DF8E: move.w  #$1e, $5a(a6)

00DF94: add.w   d2, $5c(a6)    ; белое += число собранных ГРУПП
00DF98: add.w   d2, $8c(a6)    ; та же величина в копию
00DF9C: cmpi.w  #$270f, $5c(a6); потолок 9999
00DFA2: ble.w   $dfac
00DFA6: move.w  #$270f, $5c(a6)
00DFAC: rts
```

На входе: `d1` = сколько камней собрано, `d2` = сколько ГРУПП собрано.
Проверено живым прогоном: за группу из 3 камней `d1=3`, `d2=1`.

## Отрисовка чисел

**Большое (бирюзовое), 2 цифры** — `$00DFF2`. Буфер по указателю `+0x16`.
Цифра = 2 тайла по вертикали: верх `$10 + цифра*2`, низ `+1`.
Ноль в старшем разряде не печатается.

**Белое, до 4 цифр** — `$00E03E`. Буфер по указателю `+0x20`.
Мелкий шрифт, тайл = `$26 + цифра`, цифры пишутся СПРАВА НАЛЕВО
(`move.w d0, -(a0)`), четыре места сначала очищаются.

**После конца раунда** показывается `+0x8C`, а не `+0x5C` — см. ниже почему.

## Конец раунда — `$006DA8`

```
006DA8: move.w  $ff0422.l, d7    ; число игроков в бою
006DAE: subq.w  #$1, d7
006DB0: lea.l   $ff1000.l, a0
006DB6: cmpi.w  #$18, $4c(a0)    ; завалился?
006DBC: blt.w   $6dc6
006DC0: move.w  #$1000, $5c(a0)  ; метка «выбыл» пишется В ПОЛЕ СЧЁТА
006DC6: lea.l   $400(a0), a0
006DCA: dbra    d7, $6db6

006DCE: lea.l   $ff1000.l, a0    ; дальше — кто победил
006DD4: lea.l   $ff1400.l, a1
006DDA: move.w  $5c(a0), d1
006DDE: cmp.w   $5c(a1), d1      ; в a0 остаётся тот, у кого $5C МЕНЬШЕ
006DE2: blt.w   $6dfc
006DE6: bne.w   $6df8
006DEA: move.w  $ffef90.l, d2    ; поровну — бросается монетка
006DF0: andi.w  #$1, d2
006DF4: beq.w   $6dfc
006DF8: exg.l   a0, a1
006DFA: movea.l a0, a1
006DFC: lea.l   $400(a1), a1
006E00: cmpa.l  #$ff2000, a0
006E06: beq.w   $6e12
006E0A: cmpa.l  #$ff2400, a1
006E10: bne.b   $6dda
006E12: move.b  #$1, $e1(a0)     ; флаг победителя
006E18: rts
```

Эта подпрограмма выбирает того, у кого `+0x5C` МЕНЬШЕ, и ставит ему флаг
`+0xE1` — он управляет только НАДПИСЬЮ «WIN!/LOSE». Завалившимся в `+0x5C`
принудительно пишется `$1000`, чтобы они не могли оказаться меньшими.

## Кто на самом деле раздаёт победы — `$004390`

⚠️ Победы и поражения в матче считает ДРУГОЙ код, и он смотрит НЕ на `+0xE1`
и НЕ на `+0x5C`, а на `+0x88` — порядок выбывания:

```
004390: move.w  $ff1488.l, d0     ; порядок выбывания игрока 2
004396: cmp.w   $ff1088.l, d0     ; против игрока 1
00439C: beq.w   $43c0             ; поровну -> ничья, обоим +1 в +0xDA
0043A0: bgt.w   $43b2             ; у игрока 2 больше -> победил игрок 2
0043A4: addq.b  #$1, $ff10d8.l    ; иначе игроку 1 +1 победа
0043AA: addq.b  #$1, $ff14d9.l    ;        игроку 2 +1 поражение
```

То есть в оригинале раунд выигрывает тот, кто **продержался дольше**, и только это.

## Как раунд заканчивается

```
00EC72: move.w  $ff0418.l, d0     ; вид боя
00EC7A: lea.l   $ec84(pc), a0     ; таблица правил раунда, 8 входов
00EC82: jmp     (a0)              ; в 1on1 ($FF0418 == 1) -> $ECA4

00ECA4: jsr  $ee06        ; отметить выбывших: записать им порядок в +0x88
00ECAA: jsr  $edaa        ; ← «остался ровно один живой -> ДОБИТЬ его» ($EE40)
00ECB0: bra  $ed5e        ; «все мертвы -> режим $24, конец раунда»
```

Ключ ко всему: раунд обрывается не сам по себе — игра **насильно добивает**
последнего выжившего вызовом `$EE40`. Именно этот вызов и превращается в
турнирное правило (см. `turnir.md`).

## Очередь DMA (обновление графики в кадре)

Две заявки, обрабатываются в V-Blank на `$0003F4` и `$00041C`:

| слот | d0 (куда) | d1 (длина) + признак | d2 (источник) | d3 |
|---|---|---|---|---|
| A | `$FF04A0` | `$FF04A4` | `$FF04A8` | `$FF04AC` |
| B | `$FF04B0` | `$FF04B4` | `$FF04B8` | `$FF04BC` |

Ненулевое d1 = «заявка есть»; после исполнения поле чистится. Сам DMA делает
`$003980`, и он заканчивается обязательным для Mega Drive чтением слова по
адресу источника (`$0039EA`).

Заполняет заявки анимация маскотов: `$010796`/`$0107AA`/`$0107B2`/`$01080C`
берут запись из таблицы на **`$10944`** (запись 14 байт: источник, `$97xx`,
указатель на тайлы, длина). Здесь же живёт разобранная беда — см. `turnir.md`,
раздел про мусорный номер кадра 255.

## Поиск линий — и почему верх поля не работает

Перед начислением игра зовёт подряд четыре сканера (`$00DF0C`..`$00DF1E`):

| адрес | направление | с чего начинает |
|---|---|---|
| `$00E14E` | горизонталь | `$200(a6)` + `$60` = **+0x260** |
| `$00E2CE` | вертикаль | **`$260(a6)`** |
| `$00E380` | диагональ | `$200(a6)` + `$60` + 6 |
| `$00E4EE` | диагональ | `$326(a6)` = +0x260 + 0xC6 |

**Все четыре стартуют с +0x260 — это ряд 0, первая ВИДИМАЯ строка, — и идут только вниз.**

А массив поля устроен шире: стены (`$00FF` в колонках 6-7) начинаются с ряда −6,
то есть над экраном есть **шесть скрытых рядов**. Замер `tools\topout.py`
показывает, что игра объявляет проигрыш, когда стопка достаёт до **ряда −2**.

Значит ряды −2 и −1 играбельны, но для сканеров не существуют.

⚖️ **Доказано опытом** (`tools\test_top.py`, колонка подпёрта снизу, чтобы камни
не падали):

- тройка в рядах 0,1,2 — найдена и помечена к сбору за 49 кадров;
- та же тройка в рядах −1,0,1 — **не найдена вообще**, вместо сбора раунд
  закончился и поле стёрлось.

Пометка «этот камень сейчас схлопнется» — старший бит: ячейка становится
`$8000 | цвет` (в опыте `$8004`).

## Выдача фигур и особые камни — `$00D468`

```
00D468: lea.l  $d5cc.l, a1        ; таблица наборов цветов
00D470: move.b $b0(a6), d2        ; номер набора (уровень)
00D474: asl.w  #$5, d2            ; запись набора = 32 байта
00D478: jsr    $dc80.l            ; ГПСЧ -> d2
00D47E: andi.w #$1f, d2
00D482: move.b (a1, d2.w), d2     ; цвет
00D486: move.w d2, $ce(a6)        ; ... и так для +0xD0, +0xD2

; особый камень с битом $4000 (по флагу, приходит извне)
00D4AE: bclr.b #$0, $91(a6)
00D4B4: beq.w  $d4c4
00D4B8: ori.w  #$4000, $d0(a6)    ; на СРЕДНИЙ камень

; СВЕТЯЩИЙСЯ камень — бит $1000
00D4C4: tst.b  $ff4100.l          ; общий запрет режима
00D4CA: bne.w  $d50c
00D4CE: cmpi.w #$f, $a2(a6)       ; накопитель >= 15?
00D4D4: blt.w  $d50c
00D4D8: move.w #$f, $a2(a6)       ; удержать на 15
00D4E4: move.w $ffef90.l, d0      ; случайное число
00D4EA: tst.b  $e1(a6)            ; выиграл прошлый раунд?
00D4F2: andi.w #$7, d0            ;   да  -> шанс 1 из 8
00D4FE: andi.w #$1f, d0           ;   нет -> шанс 1 из 32
00D506: ori.w  #$1000, $ce(a6)    ; на ПЕРВЫЙ камень
```

Накопитель `+0xA2` растёт на 1 с каждой уложенной фигурой (`$00D2AA`) и
упирается в 15. **Сброса при выдаче нет** — значит светящийся камень может
выпасть и не один раз за раунд, просто редко.

⚠️ Побочная связь: шанс вчетверо выше у того, у кого стоит флаг `+0xE1`
(победитель прошлого раунда). Правка `turnir.md` меняет, кому этот флаг
достаётся, — значит слегка двигает и частоту светящегося камня.

## Управление в бою

Меню **CONFIGURATION** (пункт SETTING в выборе «best of»): LAYERS · COLORS ·
STAGE · EXIT — и СПРАВОЧНЫЕ строки `ATTACK = A C`, `CYCLE = B`.

Курсор по строкам ATTACK и CYCLE **не ходит** — назначение кнопок показано, но
не меняется. Атака висит на A и C вплотную к повороту на B, поэтому её легко
задеть случайно. Отвязать можно только правкой ROM.

## Чего в игре НЕТ

**Настоящего счёта очков в бою 1on1 нет.** Есть только:

- `+0x5A` — шкала атаки, потолок **30**;
- `+0x5C` — число собранных групп, и оно же управляет силой атаки;
- `+0xD8/+0xD9` — победы и поражения в матче (`best of 3/5/7`), а они
  раздаются по порядку выбывания.

Единственный учёт длины цепочки — `asl.w #$2` на `$00DF7A`: комбо даёт
`длина*4` к шкале атаки, которая всё равно упирается в 30. **На исход матча
длина цепочки не влияет никак.** Это и достраивает правка `turnir.md`.
