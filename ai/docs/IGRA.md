# Columns III (USA) — полная сводка по игре

Единый справочник для работы над ИИ. Здесь только про **саму игру**, без правок
и модов: папка `columns3_ai` держит ПЗУ нетронутым.

Помечено, откуда что взято:
**[П]** — проверено живым прогоном в эмуляторе (в том числе заново 22.08.2026);
**[Д]** — прочитано в дизассемблере;
**[?]** — известно не до конца, требует проверки.

## 2. Режимы и главный цикл

Меню режимов: **1P MODE · 1on1 MODE · 3P · 4P · 5P · 6P · TEST MODE**.

⚠️ **[П] Режима «играть одному» в игре НЕТ.** 1P MODE — это сюжетный режим:
заставка с пирамидами, текст, дальше бой против компьютерного соперника.
Одиночной бесконечной укладки, как в обычном Columns, здесь не предусмотрено.
Как её получить — раздел 11.

Главный цикл — `$000E76` **[Д]**:

```
000E76: move.w  $ff0406.l, d0   ; НОМЕР РЕЖИМА
000E7C: lea.l   $e8e.l, a0      ; таблица режимов, 21 вход, шаг 4 байта
000E82: movea.l (a0, d0.w), a0
000E86: jsr     (a0)
000E88: bsr.w   $ee2            ; ждать кадра
000E8C: bra.b   $e76
```

`$FF0406` — номер режима **[П]**:

| значение | что |
|---|---|
| `$0C` | титульный экран |
| `$14` | выбор режима |
| `$1C` | настройка боя 1on1 (best of 3/5/7, SETTING) |
| `$20` | **сам бой** — только в нём бот и работает |
| `$24` | конец раунда |
| `$2C` | сюжетный режим 1P |

Прочие важные глобальные ячейки **[Д]**:

| адрес | что |
|---|---|
| `$FF0418` | вид боя (в 1on1 равно 1) |
| `$FF0422` | число игроков в бою |
| `$FF041E` | общий счётчик выбывания |
| `$FFEF90` | текущее случайное число |

## 3. Игровое поле

Указатель на поле лежит в структуре игрока по смещению **`+0x06`** **[П]**.
У игрока 1 это `$FF1260`, у игрока 2 — `$FF1660`.

- ячейка = **слово** (2 байта)
- ряд = **16 байт** (8 слов: 6 игровых колонок + 2 слова стены)
- поле **6 колонок × 13 рядов**; ряд 13 и ниже — пол
- **над экраном ещё 6 скрытых рядов** (ряды −6..−1), там появляется фигура

Значения ячейки **[П]**:

| значение | что |
|---|---|
| `$0000` | пусто |
| `$0001..$0006` | цвет камня |
| `$00FF` | стена или пол |
| `$8000 \| цвет` | камень помечен к схлопыванию в этом кадре |
| `$1000 \| цвет` | светящийся камень |
| `$4000 \| цвет` | особый камень |

Для бота: цвет берётся как `значение & 0xFF`, флаги — старшие биты.

## 4. Структура игрока

Пять слотов с шагом `$400`: `$FF1000` · `$FF1400` · `$FF1800` · `$FF1C00` · `$FF2000`.
В бою 1on1 заняты первые два; остальные заранее помечены «выбыл» (`+0x5C = $1000`).

| смещение | размер | что это |
|---|---|---|
| `+0x00` | слово | номер игрока |
| `+0x06` | длинное | **указатель на поле** (ряд 0 = первый видимый) |
| `+0x16` | длинное | буфер отрисовки большого бирюзового числа |
| `+0x20` | длинное | буфер отрисовки белого числа |
| `+0x24` | длинное | указатель на структуру соперника |
| `+0x42` | слово | **колонка падающей фигуры (0..5)** |
| `+0x4C` | слово | ⚠️ **НЕ «высота завала»** — счётчик снижения фигуры, см. ниже |
| `+0x4E` | длинное | указатель на клетку поля под фигурой |
| `+0x5A` | слово | шкала атаки (бирюзовое число), потолок **30** |
| `+0x5C` | слово | число собранных ГРУПП, потолок 9999; при смерти сюда пишется `$1000`. ⚠️ Именно это число код `$00E054` рисует большим белым «счётом» — поэтому на записях при завале «счёт» становится ровно 4096 и замирает |
| `+0x60/62/64` | слова | цвета текущей фигуры **при появлении**, сверху вниз |
| `+0x6C` | слово | **длина цепочки (комбо)** |
| `+0x70` | слово | **счётчик уложенных фигур** |
| `+0x76` | слово | ненулевое — начисление запрещено |
| `+0x88` | слово | порядок выбывания |
| `+0x8C` | слово | копия `+0x5C`, обнуляется по ходу раунда |
| `+0x91` | байт | флаг выдачи особого камня |
| `+0x9E` | слово | сила посланной сопернику атаки |
| `+0xA2` | слово | накопитель для светящегося камня, потолок 15 |
| `+0xB0` | байт | номер набора цветов (уровень) |
| `+0x100 / +0x120 / +0x140` | слова | ⭐ **живые цвета падающей фигуры**, сверху вниз |
| `+0xCE/D0/D2` | слова | **цвета следующей фигуры**, сверху вниз |
| `+0xD8 / +0xD9 / +0xDA` | байты | победы / поражения / ничьи в матче |
| `+0xE1` | байт | флаг «победил в раунде» — управляет надписью WIN!/LOSE |
| `+0xE3..+0xEF` | 13 байт | свободно, во время игры никто не пишет |

### ⭐ Уточнение от 22.08.2026 — важное для бота

**[П] `+0x60/62/64` — это снимок цветов на момент появления фигуры, и поворот
его НЕ меняет.** Живые цвета падающей фигуры лежат в блоке спрайтов
**`+0x100 / +0x120 / +0x140`** (шаг `$20`), туда их копирует код `$00D2AE`.
Именно их крутит кнопка поворота.

Проверено: `(3,1,4)` → `(4,3,1)` → `(1,4,3)` → снова `(3,1,4)`, и в поле легло
ровно то, что было в живых цветах. Раньше это место было размечено неверно —
бот, читающий `+0x60`, не увидел бы своих же поворотов.

**[П] `+0xCE/D0/D2` — действительно следующая фигура.** Сверено 4 раза из 4:
то, что лежало в `+0xCE`, на следующем ходу оказалось живыми цветами.

**[П] Поворот кнопкой `B` крутит тройку вниз по кругу:** `(верх, середина, низ)`
превращается в `(низ, верх, середина)`. Замер: `(3,1,4) → (4,3,1) → (1,4,3) →
(3,1,4)`, и в поле легло ровно то, что стояло в живых цветах.

⚠️ **Нажатия можно потерять.** Сразу после укладки предыдущей фигуры новая
ещё не слушается кнопок, и повороты уходят впустую. Считать нажатия нельзя —
надо жать, пока живые цвета не станут нужными (`bot_io.Hands.rotate_to`).

### ⚠️ `+0x4C` — не то, чем казалось

Старая разметка называла `+0x4C` «высотой завала». **Это счётчик снижения
падающей фигуры**: он идёт `4, 8, 12, 16, 20` и сбрасывается при укладке.
Смерть игра объявляет, когда он доходит до `$18` (24) — то есть когда фигуре
некуда опускаться.

Практический вывод, оплаченный отладкой: **держать `+0x4C` нулём нельзя.**
Если обнулять его каждый кадр, конечный автомат игры ломается, и через пять
ходов управление улетает в никуда. Придерживать можно только у самого порога.

⚠️ **Метка `+0x5C == $1000` — НЕ признак смерти.** Её пишет код `$006DC0`, когда
`+0x4C` дошёл до 24, то есть фигуре некуда опускаться **в этот момент** — например,
пока снизу подпирают слои. Игрок при этом жив и играет дальше: наблюдение 24.08 на
записи боя — число шло `4096 → 4097 → 4098`, а `+0x5C` это счётчик собранных ГРУПП,
и мёртвый их не собирает. Влияет метка только на надпись WIN!/LOSE через `+0xE1`
(см. §8), настоящие победы считает `$004390` по `+0x88`.

**Смерть определять ПО ПОЛЮ** — стопка достала ряд −2, как это делает `duel.py`
(там же, `duel.py:400`, стоит предупреждение об этой метке).

### ⚠️ Пустые слоты игроков пишут по дикому указателю

В бою заняты два слота из пяти, но отрисовка проходит по всем. У пустых слотов
указатели на буферы (`+0x16`, `+0x1C`, `+0x20`) равны нулю, и код `$00E6E8`
(`clr.l (a4)`) пишет по адресу 0. На приставке запись в картридж пропадает и
ничего не происходит; в эмуляторе она затирала обработчик прерывания строки
на `$000200`, после чего игра улетала в никуда.

Лечение — `bot_io.fix_empty_slots`: дать пустым слотам настоящие буферы в
свободной памяти. Свободные куски найдены обходом всех записей:
**`$FF8E00..$FFDFFF`** (21 КБ) и **`$FF3300..$FF7FFF`** (19 КБ).

## 5. Выдача фигур и особые камни — `$00D468` [Д]

```
00D468: lea.l  $d5cc.l, a1        ; таблица наборов цветов
00D470: move.b $b0(a6), d2        ; номер набора (уровень)
00D474: asl.w  #$5, d2            ; запись набора = 32 байта
00D478: jsr    $dc80.l            ; ГПСЧ -> d2
00D47E: andi.w #$1f, d2
00D482: move.b (a1, d2.w), d2     ; цвет
00D486: move.w d2, $ce(a6)        ; и так для +0xD0, +0xD2
```

Цвет каждого из трёх камней берётся независимо из набора на 32 позиции —
значит **частоты цветов внутри уровня неравномерны** и заданы таблицей `$D5CC`.

**Особый камень** (`$4000`, на средний камень): выдаётся по флагу `+0x91`.
**Светящийся камень** (`$1000`, на первый камень): требует накопитель `+0xA2 ≥ 15`;
шанс **1 из 8**, если игрок выиграл прошлый раунд (`+0xE1`), иначе **1 из 32**.
Накопитель растёт на 1 с каждой уложенной фигурой и не сбрасывается при выдаче,
поэтому светящийся камень может выпасть и не один раз за раунд.

**[?] Что именно делают особый и светящийся камни при схлопывании — не разобрано.**
Это **единственный** известный источник расхождения тренажёра с игрой: на
проверке 69 ходов разошлись 4, и все четыре — там, где на поле лежал камень с
битом `$1000` или `$4000`. Видно, что игра убирает камни, которых не убирает
клон, но правило пока не вскрыто.

## 5а. Уровни — игра ускоряется сама [Д][П]

Код `$00D314`:

```
00D314: cmpi.w #$14, $8c(a6)   ; собрано 20 групп?
00D31A: bge    $d328
00D31E: cmpi.w #$23, $70(a6)   ; уложено 35 фигур?
00D324: blt    $d364           ; нет -> обычная выдача
00D328: clr.w  $8c(a6)         ; ДА -> УРОВЕНЬ
00D32C: clr.w  $70(a6)
00D330: cmpi.l #$8000, $44(a6) ; скорость падения уже предельная?
00D33C: addi.l #$800, $44(a6)  ; нет -> УСКОРИТЬ
00D344: move.w #$7, $ce(a6)    ; следующая фигура = служебная метка (7,8,9)
```

Отсюда три важных для бота вещи:

1. **Счётчик `+0x70` не сквозной** — он обнуляется на каждом уровне. Как
   «сколько всего уложено» его использовать нельзя.
2. **Скорость падения растёт** (`+0x44`, шаг `$800`, потолок `$8000`). На
   высоких уровнях у бота меньше кадров, чтобы довести фигуру до дальней колонки.
3. **Служебная фигура `(7,8,9)`** — не настоящая фигура, а метка смены уровня.
   Пока она на экране, читать цвета бессмысленно: надо ждать (`wait_ready`).

Для обучения и для сверки уровень держится постоянным (обнуляем `+0x8C` и не
даём `+0x70` дойти до 35) — иначе забег идёт на разных скоростях и его нельзя
сравнивать сам с собой.

## 5б. Особые камни и подлянки — ВСКРЫТО 22.08.2026 [Д][П]

Раньше это место было белым пятном. Теперь разобрано, и оно куда богаче,
чем казалось: камней **три вида**, и они выстраиваются в цепочку.

### Камень 1 — СВЕТЯЩИЙСЯ, бит `$1000`

**Как получить** (`$00D4C4`): накопитель `+0xA2` должен дойти до 15 — он растёт
на единицу с каждой уложенной фигурой и не сбрасывается. Дальше удача:
**1 шанс из 8**, если ты выиграл прошлый раунд (флаг `+0xE1`), иначе
**1 из 32**. Ставится на **верхний** камень фигуры.

**Что делает, когда его СОБРАЛИ** (`$00D8AE`): игра берёт случайную колонку,
отступает на 3–4 ряда вниз от верха стопки и **втыкает туда камень `$2000`** —
то есть светящийся камень сам по себе ничего не ломает, он **порождает
следующий, злой камень**.

### Камень 2 — ПОДЛЯНКА, бит `$2000`

Собрал его — и срабатывает **случайный эффект из четырёх** (`$00F0C2`: берётся
случайное число, `and #7`, таблица `$00F138` на восемь входов; входы повторяют
четыре подпрограммы дважды, значит **у каждой ровно 25%**):

| эффект | код | что делает |
|---|---|---|
| **сжечь своё поле** | `$00F0D8` | помечает к сбору ВСЕ 104 клетки своего поля и возвращает себе потолок целиком (`+0x78 -= 13`) |
| **опустить потолок** | `$00F11E` | сопернику `+0x78 += 5` — поле становится на пять рядов мельче |
| **разогнать падение** | `$00F126` | сопернику `+0x44 = $10000` — это ВЫШЕ обычного потолка скорости `$8000` |
| **поднять уровень** | `$00F130` | сопернику взводится `+0x8B` — тот самый флаг смены уровня |

Три эффекта из четырёх бьют по сопернику, один спасает тебя.

### Камень 3 — ОСОБЫЙ, бит `$4000`

**Как получить** (`$009B50`) — ровно то, о чём говорят игроки:

```
009B58: cmpi.w #$3, $6c(a6)   ; ДЛИНА ЦЕПОЧКИ >= 3 ?
009B5E: bge    $9b6c          ;   да -> дать камень
009B62: cmpi.w #$4, $9e(a6)   ; ... или СИЛА АТАКИ >= 4
009B68: blt    $9bd0          ;   нет -> ничего
009B86: move.b #$1, $91(a6)   ; ← выдать особый камень
```

То есть **нужна цепочка минимум из трёх** (или накопленная атака от 4).
Ставится на **средний** камень следующей фигуры.

**У него срок годности.** Когда фигура ложится (`$00D7E2`), заводится таймер
`+0x94 = 900` кадров = **15 секунд**, и колонка запоминается в `+0x96`. Не успел
собрать — `$009BF2` снимает с камня флаг, и он становится обычным.

Сила зависит от размера цепочки: таблица `$009BD2` даёт `+0xA0` по формуле
`индекс = min(max(атака−1, цепочка) − 3, 7)`:

| цепочка | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10+ |
|---|---|---|---|---|---|---|---|---|
| в бою 1 на 1 | 900 | 1200 | 1500 | 1800 | 2100 | 2400 | 2700 | 3000 |
| у 3–6 игроков | 720 | 900 | 1080 | 1260 | 1440 | 1620 | 1800 | 1980 |

(в кадрах: 900 = 15 секунд, шаг 5 секунд)

### Куда какой бит ведёт — `$00E0EA`

При схлопывании игра смотрит на флаги собранных камней:

```
00E0F6: btst #$4, d7    ; $1000 светящийся -> +0xA6 = 1  (породить камень $2000)
00E11E: btst #$6, d7    ; $4000 особый     -> +0xA8 бит 0 (эффект из $00F03E)
00E134: btst #$5, d7    ; $2000 подлянка   -> +0xA8 бит 1 (случайная четвёрка)
```

⚠️ Проверено живым прогоном: флаг `+0x91` действительно выдаёт камень `$4000`
на средний камень (в руках читается как `4004`, `4002`, `4006`), и при укладке
заводится таймер около 884 кадров.

### Пять видов ПОРЧИ — что накладывает собранный камень `$4000`

Собранный особый камень (`+0xA8` бит 0) ведёт в `$00EFAC`, и это **система
порчи**. Таймеры лежат подряд в структуре игрока, по одному на вид:

| таймер | что делает | чем доказано |
|---|---|---|
| `+0xF0` | **меняет местами «влево» и «вправо»** (`$00EE98`: биты 2 и 3 в `+0x40/41` переставляются) | живой прогон: жму вправо — фигура едет влево |
| `+0xF2` | **отключает кнопку поворота** (`$00EEE6`: гасит бит кнопки `+0xAD`, а это именно CYCLE — `$00DAD2`) | код |
| `+0xF4` | **прячет окно «следующая фигура»** (`$00E6BE`: `clr.l (a4)` вместо отрисовки) | снимок `shots\porcha_2.png` |
| `+0xF6` | **переворачивает поле** | снимок `shots\porcha_3.png` |
| `+0xF8` | **делает поле чёрно-белым** (`$00D08C`: подменяет номер палитры на `$60`) | снимок `shots\porcha_4.png` |

Какую наложить — выбирается случайно из таблицы (`$00F03E`, пять видов, веса
разные; либо `$00F062`, четыре вида — набор зависит от вида боя).

⭐ **Длительность порчи берётся из таблицы по ДЛИНЕ ЦЕПОЧКИ** (`$00F00C`:
`add.w $a0(a6), (a1,d0)`). То есть цепочка из трёх даёт 15 секунд порчи, а
цепочка из десяти — 50. И если наложить ту же порчу повторно, время
СКЛАДЫВАЕТСЯ.

### ⭐ Флаг `+0x8B` — «уровень поднят» и три его последствия

Эффект «поднять сопернику уровень» (`$00F130`) ставит сопернику `+0x8B` бит 0.
Этот флаг бьёт сразу по трём местам:

**1. Ломает особый камень в руках** (`$00D2E0`):

```
00D2E0: tst.b  $8b(a6)        ; уровень поднят?
00D2E4: beq.w  $d30a
00D2E8: bclr.b #$6, $20(a5)   ; ← СНЯТЬ флаг $4000 со среднего камня
00D2F2: bclr.b #$6, $62(a6)
00D2F8: clr.w  $94(a6)        ; и погасить его таймер
```

⚠️ **Проверено живым прогоном на ОДНОЙ И ТОЙ ЖЕ фигуре:**

| `+0x8B` | что пришло в руки |
|---|---|
| 0 | `0004` **`4004`** `0003` — особый камень на месте |
| 1 | `0004` `0004` `0003` — **флаг `$4000` содран** |

**2. Золотая фигура перестаёт засчитываться** (`$00D286`): если `+0x8B` стоит и
пришла золотая фигура (первый «цвет» = 7), игра ставит `+0xAB = 1` и **выходит,
не положив фигуру и не увеличив счётчик** `+0x70`.

**3. Гасится таймер особого камня** — даже если он уже лежал на поле.

Отсюда и ощущение игроков, что «подлянка на уровень» отбирает сразу всё: она
не просто отнимает ряды, она **обнуляет твою заготовку**.

### Золотая фигура — `7, 8, 9`

Та самая, что приходит каждые 20 собранных групп (или 35 фигур). В памяти это
не цвета, а **три служебных значения 7, 8, 9** — поэтому обычный бот, читающий
цвета как 1..6, видит на их месте мусор и должен просто переждать.

Выдаётся двумя путями: сама по себе при повышении уровня (`$00D344`) и по флагу
**`+0xC9` бит 0** (`$00D30A`) — этот флаг ставит отдельное действие `$011930`.

### ⭐ ГЛАВНОЕ: всё это включается настройкой LAYERS

В меню CONFIGURATION есть строка **LAYERS**, и по умолчанию она равна **0**.
Значение крутится кнопками `A`/`C` (назад — `B`), диапазон **0..5**, отдельно
для каждого игрока; лежит в **`$FF0460`** (1P) и **`$FF0461`** (2P) и попадает
в `+0x7E` — начальное число отнятых рядов.

⚠️ **При LAYERS = 0 вся эта механика мертва.** Золотая фигура падает как три
мусорных камня `7, 8, 9`, не слушается кнопок и ничего не делает — я на этом
и споткнулся в первый раз. Со слоями она сразу оживает.

Проверено: выставили LAYERS = 3 обоим — в бою `+0x7E = 3` у обоих, внизу полей
видны зелёные полосы слоёв, и золотая фигура начинает слушаться.

### Три варианта золотой фигуры — `$00D724`

**Решает НИЖНИЙ сегмент**, а поворот кнопкой `B` меняет, какой из трёх окажется
внизу. Проверено живьём: `0007 0008 0009` → `0009 0007 0008` → `0008 0009 0007`.

Эффект срабатывает **в момент касания стопки**:

```
00D724: cmpi.b #$7, d0        ; значение < 7 -> обычный камень
00D72C: ori.w #$8000, ...     ; все три сегмента помечаются к сбору
00D73C: cmpi.w #$7, d0
00D740: beq $d790             ; ← ВАРИАНТ 7
00D744: cmpi.w #$9, d0
00D748: beq $d7c4             ; ← ВАРИАНТ 9
00D74C: move.b $11(a4), d1    ; ← ВАРИАНТ 8: цвет камня, КОТОРОГО КОСНУЛАСЬ
00D758: move.w #$67, d7       ;   обойти все 104 клетки
00D75C: cmp.b $1(a0), d1      ;   тот же цвет?
00D764: btst #$6, (a0)        ;   не особый ($4000)
00D76C: btst #$5, (a0)        ;   и не подлянка ($2000)
00D774: bset #$7, (a0)        ;   -> пометить к сбору
```

| внизу | что делает | чем доказано |
|---|---|---|
| **7** | **дать сопернику слои** (`+0x90` бит 0 → `+0x78 += 2`), причём сразу двум соперникам в играх на много человек | код `$00D790` |
| **8** | **убрать с поля ВСЕ камни того цвета, которого коснулась** | живой прогон: цвет 3 исчез целиком (`{1:2, 2:4, 3:3, 5:3, 6:1}` → `{1:2, 2:1, 5:3, 6:1}`) |
| **9** | **снять слои себе** (`+0x78 -= 3`) | код `$00D7C4` |

Особые камни (`$4000`) и подлянки (`$2000`) вариант 8 **не трогает** — они
специально исключены проверками битов 6 и 5.

## 5в. Атака и потолок поля — как «поднимают уровень» [Д]

Справка в меню (`ATTACK = A C`) не врёт: атака висит на кнопке, номер которой
лежит в `+0xAF` (а также `+0xAD`, `+0xAE` — в играх на 3–6 человек ими выбирают,
КОГО бить). Код `$00E9D8`:

```
00E9DC: move.b $af(a6), d0    ; номер кнопки атаки
00E9E0: btst.l d0, $41(a6)    ; нажата?
00EA10: move.w $5a(a6), d0    ; ШКАЛА АТАКИ (потолок 30)
00EA14: cmpi.w #$a, d0        ; меньше 10 — не хватает
00EA1E: subi.w #$a, d0        ; делим на 10: d1 = сколько ступеней
00EA2E: move.w d0, $5a(a6)    ; остаток остаётся на шкале
00EA38: sub.w  d1, $78(a6)    ; СЕБЕ  -d1
00EA4A: add.w  d1, $78(a4)    ; СОПЕРНИКУ +d1
```

**Цена одной ступени — 10 очков шкалы**, шкала упирается в 30, значит за раз
можно передать самое большее **три ступени**.

Что такое ступень (`$00EAC8`): накопленное `+0x78` перетекает в **`+0x7E` —
уровень потолка, 0..13**. А `+0x7E` буквально **сдвигает указатель на поле**:

```
00945E: move.w d1, $7e(a6)
009462: asl.w  #$4, d1        ; ступень = 16 байт = ОДИН РЯД
009464: add.l  d1, $6(a6)     ; ← поле начинается ниже
```

То есть «поднять сопернику уровень» — это **отнять у него ряды поля**.
Чем выше `+0x7E`, тем мельче поле и тем быстрее завал. Себе ступени вычитаются,
то есть удачная атака ещё и возвращает собственные потерянные ряды.

### Почему это важно для ИИ

Во второй фазе (бой 1 на 1) сеть обязана считаться с тем, что:

* **поле может стать мельче в любой момент** — клон правил с жёсткими 13 рядами
  для боя не годится, глубину надо брать из `+0x7E`;
* **скорость падения может скакнуть выше штатного потолка** — времени на
  доводку фигуры станет меньше;
* **копить шкалу до 30 и бить тремя ступенями сразу выгоднее**, чем бить по
  одной: остаток ниже 10 всё равно лежит мёртвым грузом;
* **цепочка из трёх — это не только очки, но и пропуск к особому камню**, а у
  него всего 15 секунд жизни. Значит у сети появляется настоящий выбор между
  «схлопнуть сейчас по мелочи» и «собрать цепочку и получить камень».

Это ровно то, из-за чего игра тяжелее, чем выглядит: одиночная укладка —
задача про аккуратность, а бой — про размен ресурсами со сроком годности.

## 6. Поиск линий — и главная причуда игры [Д][П]

Перед начислением игра зовёт подряд четыре сканера (`$00DF0C..$00DF1E`):

| адрес | направление |
|---|---|
| `$00E14E` | горизонталь |
| `$00E2CE` | вертикаль |
| `$00E380` | диагональ |
| `$00E4EE` | вторая диагональ |

⚠️ **Все четыре стартуют с ряда 0 — первой ВИДИМОЙ строки — и идут только вниз.
Шести скрытых рядов над экраном они не видят вообще.**

Смерть объявляется, когда стопка достаёт до ряда −2. Значит ряды −2 и −1
играбельны, но собрать в них линию невозможно.

**[П] Доказано опытом** (колонка подпёрта снизу, чтобы камни не падали):
тройка в рядах 0,1,2 — найдена и схлопнулась за 49 кадров; та же тройка в
рядах −1,0,1 — не найдена вообще.

Копия правил для тренажёра **обязана повторить эту причуду**, иначе сеть будет
рассчитывать на сборы, которых в настоящей игре не бывает.

## 7. Начисление — `$00DF62` [Д][П]

```
00DF62: tst.w   $76(a6)        ; начисление запрещено? -> выход
00DF6C: tst.w   $6c(a6)        ; есть цепочка?
00DF76: move.w  $6c(a6), d2
00DF7A: asl.w   #$2, d2        ; длина цепочки * 4
00DF7C: add.w   d2, d1         ; ВЕСЬ бонус за комбо, какой есть в игре
00DF80: add.w   d1, $5a(a6)    ; шкала атаки += камни + цепочка*4
00DF84: cmpi.w  #$1e, $5a(a6)  ; потолок 30
00DF94: add.w   d2, $5c(a6)    ; групп += собрано групп
00DF9C: cmpi.w  #$270f, $5c(a6); потолок 9999
```

На входе `d1` = сколько камней собрано, `d2` = сколько групп.
**[П]** За группу из трёх камней: `d1 = 3`, `d2 = 1`.

**Настоящего счёта очков в бою нет.** Есть шкала атаки с потолком 30 и число
групп. На исход матча длина цепочки не влияет — она лишь быстрее упирает шкалу
в потолок.

## 8. Конец раунда и раздача побед [Д]

`$006DA8` — помечает завалившихся (`+0x4C ≥ $18` → в `+0x5C` пишется `$1000`) и
ставит флаг `+0xE1` тому, у кого `+0x5C` меньше. **Но этот флаг управляет только
надписью WIN!/LOSE.**

Настоящие победы считает `$004390`, и смотрит он на `+0x88` — **порядок
выбывания**. Кто продержался дольше, тот и выиграл раунд. Больше ничего.

Правила раунда — таблица на `$00EC84`, для 1on1 (`$FF0418 == 1`) вход `$00ECA4`:

```
00ECA4: jsr  $ee06        ; отметить выбывших: записать порядок в +0x88
00ECAA: jsr  $edaa        ; ← «остался ровно один живой -> ДОБИТЬ его» ($EE40)
00ECB0: bra  $ed5e        ; «все мертвы -> режим $24, конец раунда»
```

⭐ **Ключ к одиночному режиму.** Раунд обрывается не сам по себе: игра
**насильно добивает последнего выжившего** вызовом `$00EDAA`. Убрать этот вызов —
и оставшийся в одиночестве игрок будет играть, пока сам не завалится.

## 9. Управление [П]

Меню CONFIGURATION показывает раскладку: **`ATTACK = A C`, `CYCLE = B`**.
Курсор по этим строкам не ходит — переназначить кнопки нельзя.

Замеры управления, сделанные 22.08.2026 на нашем эмуляторе:

| действие | как |
|---|---|
| сдвиг на колонку | тап «влево»/«вправо»: 2 кадра нажато + 2 отпущено |
| поворот цветов | тап `B`, тем же тактом; крутит `+0x100/120/140` вниз по кругу |
| ускоренное падение | удержание «вниз» |
| вся постановка фигуры | **55–65 кадров** от появления до укладки |

⚠️ Кнопку нельзя держать: игра засчитывает удержание за одно нажатие.
Каждый ход — обязательный такт «нажал / отпустил».

⚠️ Атака висит на `A` и `C` вплотную к повороту на `B` — живой игрок задевает её
случайно. Боту это безразлично, он жмёт только то, что нужно.

## 10. Что нужно боту — короткий список

Всё, что ИИ читает каждый ход:

| что | откуда |
|---|---|
| поле 6×13 плюс 6 скрытых рядов | `[+0x06]`, ячейка = слово, ряд = 16 байт |
| цвета текущей фигуры | `+0x100 / +0x120 / +0x140` |
| цвета следующей фигуры | `+0xCE / +0xD0 / +0xD2` |
| колонка фигуры | `+0x42` |
| ход закончился | изменился `+0x70` |
| смерть | `+0x4C ≥ 24` |
| идёт ли бой | `$FF0406 == $20` |

Всё, что ИИ нажимает: влево, вправо, `B`, вниз. **Ходов на фигуру ровно 18**
(6 колонок × 3 поворота); с учётом следующей фигуры — 324 пары.

## 11. Как получить игру в одиночку

Раз режима нет, его надо сделать. Два пути, оба опираются на раздел 8.

**Путь А — без единой правки ПЗУ (песочница в обвязке).**
Заходим в 1on1, а второго игрока держим безвредным прямо из эмулятора: каждый
кадр чистим его поле и обнуляем шкалу атаки. Он не завалится и не пришлёт
мусор, раунд не кончится, игрок 1 укладывает фигуры сколько угодно.
ПЗУ при этом остаётся байт в байт ванильным. Годится для обучения.

**Путь Б — настоящий режим в ПЗУ.** Убрать вызов `jsr $edaa` на `$00ECAA`
(«добить последнего выжившего») при числе игроков 1 и завести пункт меню.
Нужен пересчёт контрольной суммы (`tools/patch.py` это умеет). Выглядит на видео
честнее: чужого поля на экране просто нет.

| что | где описано | чем доказано |
|---|---|---|

| светящийся камень `$1000` | раздел 5б | код `$00D8AE` |
| подлянка `$2000` — четыре случайных эффекта | раздел 5б | таблица `$00F138`, сверена побайтово |
| особый камень `$4000` — пять видов порчи | раздел 5б | код `$00EFAC` + четыре снимка экрана |
| как приходит мусор от соперника | раздел 5в | это не мусор в поле, а СЛОИ: сдвиг указателя поля |
| растёт ли скорость падения | раздел 5а | да, `+0x44 += $800` каждый уровень, потолок `$8000` |

Про золотую фигуру ещё раз, словами игрока — сходится с кодом дословно:

* **внизу 9** — убирает плиты снизу у себя (`$00D7C4`, `+0x78 -= 3`);
* **внизу 8** — убирает с поля ВСЕ камни того цвета, которого коснулась (`$00D74C`);
* **внизу 7** — даёт плиты сопернику (`$00D790`, ему `+0x78 += 2`).

Что окажется внизу — решает поворот кнопкой `B`, а срабатывает в момент
касания стопки.

### Ещё НЕ выяснено

- **[?]** насколько силён компьютерный соперник в 1P MODE и на сколько ходов
  он считает;
- **[?]** что именно делает эффект `+0xA8` бит 0 от камня `$4000` в играх на
  3–6 человек (таблица `$00F062`, четыре вида вместо пяти);
- **[?]** зачем нужен байт `$FF0444` — он гасит четвёрку действий на `$0118BA`,
  но настройкой LAYERS не меняется (LAYERS живёт в `$FF0460`/`$FF0461`);
- **[?]** переходное значение `0101` в поле — им игра помечает камень в полёте
  между рядами; смысла двух байт не разбирал.

Ничего из этого для боя 1 на 1 не требуется.

## 14. Оговорка про точность эмулятора

`tools\md_machine.py` — **не тактовый** эмулятор. Настоящая Mega Drive отмеряет
кадр по тактам процессора, а здесь на кадр отпускается фиксированное число
инструкций (13 000), подогнанное на глаз.

Логика игры от этого не ломается — она управляется кадрами, а не тактами, — но
**длительности могут отличаться от железа**: сколько кадров занимает падение,
схлопывание, анимация. Для обучения это безразлично (бот читает память и
действует по кадрам), но означает, что мы играем в «Columns III на этом
эмуляторе», а не такт в такт в неё же на приставке.

Если понадобится точность до кадра — например для записи финального видео —
нужно брать честный эмулятор (BizHawk с ядром Genesis Plus GX) и водить бота
через него.
